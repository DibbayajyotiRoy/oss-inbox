Open source. Apache-2.0. Self-hosted.

GitHub issue triage that proves itself before it acts.

OSS Inbox is a GitHub App that labels, routes and screens issues and pull requests, and never closes anything. It shows its confidence on every decision and acts only on questions it has measured against your repo's own history.

Self-host with Docker View on GitHub

Reports got cheap to write. Reading them is still your job.

Bug and security reports now arrive faster than anyone can read them, and many are invalid or duplicates.

OSS Inbox takes the repetitive part of that. It does not take your decisions away, and it does not talk.

  1. Early 2026

    curl ended its bug bounty after a flood of them.

  2. Oct 1, 2026

    Google stopped accepting product reports to its open-source VRP, for the same reason.

  3. Every week

    Most projects cannot close the door like that. They label, chase missing details, check PRs against CONTRIBUTING, route issues to the right team, and read reports that cite functions that do not exist. CI agents add to the pile by filing the same failure again and again.

Typed questions in. A threshold decides.

Follow one decision from event to action.

  1. An event arrives

    A new issue, a PR, a push, or a CI failure posted to the gate.

    issues.opened #1234

  2. It asks typed questions

    One call per item asks every enabled question: what kind of issue is this, are there steps to reproduce, does this PR follow our rules. Each answer maps to a fixed action, so there is nothing for a report to talk its way into.

    issue.type

  3. Every answer has a confidence

    The probability of the chosen answer, stored with the decision and shown in the dashboard.

    bug 0.94

  4. A threshold decides

    In auto mode, an answer at or above your threshold acts, if its question has been measured on your history. Everything else queues with suggested answers and the confidence shown. Set it per question in .github/oss-inbox.yml.

    0.94 >= 0.90: act

Six promises, each one checkable.

Each one points at a setting or a code path you can read.

Shadow by default

It records what it would do and changes nothing until you set a feature to auto.

mode: shadow0changes until auto

Never closes anything

No closing, deleting, locking or transferring. Those are not code paths in the app. Duplicate links and transfers are suggestions you accept.

no close path0close paths

Measured before auto

It replays your closed issues and merged PRs. A question needs measured examples, and accuracy at or above its threshold, before it may act.

min_samples: 3030or more examples

Visible comments

Comments are off unless you turn them on. When on, each one is plain text that ends with a link to the decision behind it.

comments: false0comments until you opt in

Config in your repo

One YAML file in your repo, org defaults in .github. The app has no write access to repo contents, and a typo falls back to defaults that never act.

.github/oss-inbox.yml0contents writes

Untrusted input stays untrusted

Report text is data. Each answer maps to a fixed action, so a report cannot instruct the app to do something else.

fixed actions1action per answer

Stopping it takes one line

Set a feature to off, or set DRY_RUN=true and restart. Even auto then only records what it would have done.

DRY_RUN=true0actions

Backfill accuracy is an upper bound: only items your maintainers labeled are counted, and live traffic is messier. The dashboard says so next to the number.

Quickstart.

About five minutes with Docker Compose. You need Docker with Compose v2, a TypeSafe API key, and a GitHub account or org that can own an App.

  1. 1

    Start the stack

    Keep DRY_RUN=true at first.

    shell
    git clone \
  https://github.com/DibbayajyotiRoy/oss-inbox.git
cd oss-inbox
# set TYPESAFE_API_KEY and SESSION_SECRET
cp .env.example .env
docker compose up -d --build
  2. 2

    Create the GitHub App

    Open http://localhost:8000/api/setup and click Create GitHub App. GitHub's manifest flow writes the credentials to .env. Then restart and install the app on one repo. GitHub cannot reach localhost, so forward webhooks with smee or a tunnel.

    shell
    docker compose restart api worker
  3. 3

    Measure it on your history

    Open the dashboard at http://localhost:3000, run the backfill for that repo and read the calibration view. The backfill changes nothing on GitHub. The CLI prints an accuracy table too.

    shell
    docker compose exec api \
  python -m app.cli eval \
  OWNER/REPO --limit 200
  4. 4

    Switch one feature to auto

    Every feature starts in shadow. Set DRY_RUN=false too, then watch the queue.

    .github/oss-inbox.yml
    # .github/oss-inbox.yml
features:
  # off | shadow | auto
  issue_triage: { mode: auto }
# silent unless you opt in
comments: false
evaluation:
  # only act on measured questions
  require_evaluation: true
  min_samples: 30

Will it close my issues?

No. It never closes, deletes, locks or transfers anything, because the app has no way to do any of those.

Will it accuse contributors of using AI?

No. It never says who or what wrote a report, and it does not profile reporters. It asks whether a report is actionable: reproducible, grounded in your repo, backed by evidence. A careful human report that fails those questions is treated like any other that fails them.

What data goes to the model?

The item's title and body (truncated), your contributing rules, and a few repo facts. The item's current labels are not sent. The exact text of every run is visible in the dashboard and purged after your retention window.

Does it work on private repos?

Yes, after an admin acknowledges that private content will be sent to the decision backend. Private repos are off until then.

What happens when it is wrong?

Override it in the dashboard. Your answer becomes ground truth and measured accuracy updates. A question that falls below its threshold stops acting on its own.

What does it cost?

The software is free under Apache-2.0. Model calls are billed by your backend. Jev input is priced at $0.042 per million tokens at the time of writing, so 1,000 items at 3,000 tokens each is about $0.13 of input. Check TypeSafe's pricing for current rates.

Who makes Jev?

Jev is a model by TypeSafe AI. OSS Inbox is an independent open-source project, not affiliated with TypeSafe AI. An Anthropic Claude fallback exists and is marked uncalibrated.

How do I uninstall it?

Uninstall the GitHub App. The app deletes the org's stored data on the uninstall event. Labels it applied stay on your issues, and you can delete .github/oss-inbox.yml.

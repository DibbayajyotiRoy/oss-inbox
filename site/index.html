Open-source GitHub issue triage bot

GitHub issue triage that proves itself before it acts

Jev Triage is a self-hosted GitHub App that labels, routes and screens issues and pull requests. It shows its confidence, starts in shadow mode, and never closes anything.

Self-host in 5 minutes View on GitHub

Apache-2.0. Free. Runs on your machine with Docker Compose.

AI made reports cheap to write. Reading them is still your job.

Automated tools now file bug and security reports at scale, and many are invalid or duplicates. curl ended its bug bounty in early 2026. Google stopped accepting product reports to its open-source VRP on October 1, 2026. Both pointed to floods of low-quality automated submissions.

Most projects cannot shut the door. They label, ask for missing details, check PRs against CONTRIBUTING, route issues to the right team, and now also read reports that cite functions that do not exist. CI agents add to it by filing the same failure again and again.

Jev Triage takes the repetitive part of that. It does not take your decisions away, and it does not talk.

How it works

  1. An event arrives

    A new issue, a PR, a push, or a CI failure posted to the gate.

  2. It asks typed questions

    "What kind of issue is this?" "Are there steps to reproduce?" "Does this PR follow our rules?" One call to the pinned model, many questions.

  3. Every answer has a confidence

    The probability of the chosen answer, stored with the decision and shown in the dashboard.

  4. A threshold decides

    If the feature is in auto, confidence clears your threshold, and the question has been measured on your history, it acts. Otherwise it queues the item with suggested answers.

What it decides

  • Issue triage. Bug, feature, question or docs. Reproduction steps, version, logs. Applies needs-info.
  • PR checks. Breaking change, follows your contributing rules, plus exact checks in plain code: tests, docs, diff size, CODEOWNERS.
  • Routing. Which repo, which area, who owns it. Transfers are suggestions.
  • Inbound report gate. Reproducible, grounded in this repo, known non-issue, claim supported, security claim, duplicate. Security-looking outside reports are held, never filed publicly.
  • CI gate. Code bug, flaky test or infrastructure. Same as an open issue? One issue instead of five, with an hourly cap.
  • Priority and spam. p0 to p3. Spam is off until you turn it on.

Safety promises

  • Shadow by default

    It records what it would do and changes nothing until you set a feature to auto.

  • Never closes anything

    No closing, deleting, locking or transferring. Duplicate links and transfers are suggestions you accept.

  • Measured before auto

    It replays your closed issues and merged PRs. A question needs enough measured examples at or above its threshold before it may act.

  • Silent and visible

    Comments are off unless you turn them on. When on, they are plain text with a link to the decision behind them.

  • Config you can review

    One YAML file in your repo, org defaults in .github. The app has no write access to repo contents.

  • Untrusted input stays untrusted

    Report text is data. Each answer maps to a fixed action, so a report cannot instruct the app to do something else.

Backfill accuracy is an upper bound: only items your maintainers labeled are counted, and live traffic is messier. The dashboard says so next to the number.

Quickstart

You need Docker with Compose v2, a TypeSafe API key, and a GitHub account or org that can own an App.

git clone https://github.com/YOUR-ORG/jev-triage.git && cd jev-triage
cp .env.example .env     # set TYPESAFE_API_KEY and SESSION_SECRET; keep DRY_RUN=true
docker compose up -d --build
  1. Open http://localhost:8000/api/setup and click Create GitHub App. GitHub's manifest flow writes the credentials to .env.
  2. Run docker compose restart api worker, then install the app on one repo.
  3. Open the dashboard at http://localhost:3000, run the backfill, and read the calibration view.
  4. Switch one feature to auto in your config:
# .github/jev-triage.yml
features:
  issue_triage: { mode: auto }    # off | shadow | auto  (default: shadow)
comments: false                   # silent unless you opt in
evaluation:
  require_evaluation: true        # act only on questions measured on your history
  min_samples: 30

FAQ

Will it close my issues?

No. It never closes, deletes, locks or transfers anything. Those are not code paths in the app.

Is this AI slop detection?

No. It asks whether a report is actionable: reproducible, grounded in your repo, backed by evidence. It never says a report was written by an AI, and it does not profile reporters.

What data goes to the model?

The item's title and body (truncated), your contributing rules, and a few repo facts. The item's current labels are not sent. The exact text of every run is visible in the dashboard and purged after your retention window.

Does it work on private repos?

Yes, after an admin acknowledges that private content will be sent to the decision backend. Private repos are off until then.

What happens when it is wrong?

Override it in the dashboard. Your answer becomes ground truth and measured accuracy updates. A question that falls below its threshold stops acting on its own.

What does it cost?

The software is free under Apache-2.0. Model calls are billed by your backend. Jev input is priced at $0.042 per million tokens at the time of writing, so 1,000 items at 3,000 tokens each is about $0.13 of input. Check TypeSafe's pricing for current rates.

Who makes Jev?

Jev is a model by TypeSafe AI. Jev Triage is an independent open-source project, not affiliated with TypeSafe AI. An Anthropic Claude fallback exists and is marked uncalibrated.

How do I uninstall it?

Uninstall the GitHub App. The app deletes the org's stored data on the uninstall event. Labels it applied stay on your issues, and you can delete .github/jev-triage.yml.
